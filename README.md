# Glissform website

The website is a Vite, React, TypeScript, and SCSS project. Its desktop page follows the [Figma design](https://www.figma.com/design/IkSrf5xF80j0PeRMzPytZ8/Untitled?node-id=56-2717) and adds fixed Customisable, Private, and F.A.Q navigation. As soon as scrolling begins, the same navbar smoothly gains a translucent, blurred material and removes it again at the top. The selected link follows the linked section occupying the largest visible area; the brand returns to the top and clears the selection. Below 1156px, the site shows only the Glissform logo and a MacBook viewing message. The clickable feature cards switch between still previews every ten seconds, with a slim progress bar, smooth automatic and manual preview transitions, and matching hover, pressed, and keyboard-focus feedback. The Customisable grid has interactive blur choices, a starting-angle slider, and switches; timing values are illustrations.

The dedicated [Seamless Close section](https://www.figma.com/design/IkSrf5xF80j0PeRMzPytZ8/Untitled?node-id=96-45) places one large MacBook directly on the page. Native CSS sticky positioning holds its scene while GSAP ScrollTrigger turns downward scrolling into physical lid closure, with a gradual camera tilt, an aluminium back, keyboard deck and contact shadow. The desktop perspective and blur follow the same gesture. The eased motion stays closed at the end and opens only when scrolling back up; it has no automatic return segment. Stationary text behind the lid reads “A Little Magic Every Time You Close” and gently fades in as the lid reveals it, using the existing pose without changing motion or scroll timing. The WebGL2 preview uses the bundled app wallpaper and projection model, never the visitor's screen. It draws only when the pose or size changes, keeps the wallpaper texture at its source resolution, and caps the model canvas at 2× pixel density. Reduce Motion, unavailable WebGL2, image-load failure or a lost graphics context leave a still preview in normal page flow, without pinning. The layout scales to shorter desktop viewports. This section was published to glissform.app on 2026-10-01.

The silver model follows [Apple’s MacBook Air product views](https://www.apple.com/macbook-air/) and [hardware specifications](https://www.apple.com/macbook-air/specs/): slim enclosure and display borders, a six-row 78-key ANSI layout with Touch ID and inverted-T arrows, a large inset trackpad, a recessed front opening, and a reflective lid mark. Continuous rounded side walls join the lid faces and connect the keyboard deck to the front edge, preventing white gaps as the model turns. The lower enclosure curves inward toward the underside, including around the front corners. The animated geometry is rendered in one WebGL canvas with baked surface artwork matching the CSS model; the animation timing is unchanged. `public/assets/macbook-lid-mark.svg` uses the Apple mark from Apple’s site to identify the illustrated hardware.

Section headlines and the lid-reveal message use title case and one sentence or phrase without a final period. Headlines occupy at most two lines, with a shorter first line when split. Card titles, buttons, privacy facts and FAQ questions use sentence case, preserving product and system names. Card titles follow the same single-phrase punctuation and line-balance rules; FAQ questions keep question marks. Supporting copy combines the Figma design’s specific explanations with the website’s warmer tone, including visible beta requirements, precise background-running behaviour and installation guidance.

Primary download buttons lift gently, brighten and show one soft light sweep on pointer hover. Each sweep begins at the left edge immediately on hover, without an opacity fade-in, eases across over 650ms and finishes beyond the right edge; re-entering or releasing a press while still hovered starts a fresh sweep. Their blue glow expands on hover, disappears on press and smoothly returns on release. Pressing adds a small compression and hides the white border while retaining the inner highlight. Primary buttons use the navbar button’s smooth timing and springy return with more restrained scaling: hover lifts by 1.5px at 1.008 scale over 360ms; pressing settles down 0.75px at 0.985 scale over 180ms. Hover and return use cubic-bezier(.2, 1.35, .4, 1), with a 600ms return on pointer exit; pressing uses cubic-bezier(.2, .8, .3, 1). The longer settling tails and gentler rebound soften the end of each movement without changing its final size or position. Brightness, shadows, border and shimmer opacity retain their 150ms ease transitions on press. Reduce Motion keeps color and glow feedback and removes movement and the light sweep.

The navbar’s secondary download button keeps its pale blue glass appearance and fits its text label with 16px padding on each side. On pointer hover, a reflection follows the cursor, the rim catches light, and the glass lifts and tilts slightly with one entry light sweep. Pressing compresses the glass, removes its outer shadow and deepens the inner shading; release restores it with a soft rebound. The clickable area stays fixed while the glass and contents move. Keyboard focus has a visible outline and brighter material. Reduce Motion removes tilt, lift, compression and the light sweep while retaining immediate material feedback. Pointer tracking runs only on input and resets on exit, cancellation, blur, visibility changes and input-preference changes.

The final download card uses a deep navy background with softly dispersed, slowly shifting blue and violet light and 40 drifting stars in varied sizes. Nearby stars gently lean toward the pointer and brighten, returning to their positions when it leaves. Hovering or focusing the shared primary button subtly strengthens the light. Decorative animations pause outside the viewport and while the page is hidden; Reduce Motion keeps the atmosphere still and disables pointer tracking. A quiet brand row pairs a 28px app icon with the Glissform name above the pure-white, 56px “A Little More Magic” headline. The headline and narrower supporting copy form one group, with 16px between them and 32px separating that group from the brand and primary button. Card padding is 72px vertically and 64px horizontally. The “Feels At Home” cards use the Figma wording: “Start at login”, “Settings, close by”, “Keep effects ready” and “Update your way”, with their corresponding descriptions.

The animation renderer now draws the complete MacBook in one WebGL2 canvas. The rounded shell contours, 78 unlabeled keycaps, Touch ID, trackpad, camera notch, lid mark, materials and hinge/camera poses retain the existing model layout. Static surface artwork is baked once; the original full-resolution wallpaper shader renders to a texture in the same WebGL context. The screen, notch and enclosure share a depth buffer. There are no per-frame worker bitmap transfers or CSS 3D hardware transforms. Native sticky positioning retains the existing scroll distance, `power1.inOut` easing and 0.4-second scrub. GPU resources are released when the animated view is disabled; failed image/graphics initialization or context loss leaves the unpinned still preview. Published to glissform.app on 2026-10-01 after owner approval. Live HTML and bundle bytes match the production build; the single-canvas renderer was verified in the live browser.

Surface rendering refinement: the deck and both lid faces now use rounded geometry that shares its boundary with the enclosure walls. Opaque surface artwork extends beyond that boundary so filtered transparency cannot spill past the shell. The screen and camera notch are composited into one opaque lid face, removing the separate transparent aperture. Hardware and screen textures use anisotropic filtering when supported, with mipmaps refreshed when the wallpaper changes. The intentional wallpaper blur, canvas resolution cap, hardware proportions and animation timing remain unchanged.

Earlier CSS-layer and worker optimizations did not resolve the owner-reported Safari lag, despite improved callback measurements. Those measurements must not be treated as proof of smooth displayed frames. The single-canvas rewrite has passed local visual checks for geometry, closed-lid opacity, camera notch, reversal, shorter desktop layout, breakpoint cleanup/reinitialization and graphics-loss fallback in the background browser. The owner approved production publication. Dedicated Safari performance testing of this rewrite remains unverified.

For development checks, open `/?motion-benchmark`. **Measure MacBook animation** runs a warm close/open cycle followed by a measured cycle using immediate scroll positions. Its output measures animation callback spacing, not displayed frames. Pose buttons allow fixed-position visual inspection, **Freeze wallpaper for isolation** retains the current wallpaper texture while the hardware moves, and **Test graphics fallback** deliberately loses the local WebGL context. Reload to restore the animated preview. These controls are excluded from production.

Run `npm ci` and `npm run dev` here to preview it, or `npm run build` to create `dist/`.

The public server serves `/var/www/glissform.app`. Publish `dist/assets/` before replacing `index.html`, so the new page never refers to files that are not yet available. Preserve the existing `downloads/` and `updates/` directories: they contain the public DMG and signed app update feed. Update the download URL in `src/App.tsx` only when a new public version and its DMG are available.

Inter is included as a local web font under its [SIL Open Font License](public/assets/inter-license.txt). This license applies to the font, not to the Glissform source repository.

## Source and automatic deployment

The canonical source is the private repository `itsgeorge22/glissform-website`. Develop in `/Users/george/Projects/glissform-website`. Pushes to `main` and manual runs of **Deploy website** build committed source with Node 22 and publish to glissform.app. Check the Actions run before calling deployment complete.

`WEBSITE_DEPLOY_SSH_KEY` is a repository Actions secret for a dedicated website account. The server accepts only `deploy <commit SHA>` through `scripts/receive-deploy.py`; shell commands and SSH forwarding are disabled. The pinned public host key is in `config/production-known-hosts`. Credentials, generated builds and dependencies are excluded from Git.

The receiver accepts only `index.html` and `assets/`, publishes assets first and atomically replaces the page. It retains older assets and preserves `downloads/` and `updates/`. `/deployment.json` identifies the published commit. Native app source and release deployment remain separate.
